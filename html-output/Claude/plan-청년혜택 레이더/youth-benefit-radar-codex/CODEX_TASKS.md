# CODEX_TASKS.md — 개발 작업 목록

## Phase 0 — 저장소 이해
- [ ] README와 docs를 읽고 제품 목표를 요약한다.
- [ ] `src/data/policies.js`의 목업 정책 DB 구조를 확인한다.
- [ ] `src/features/matching.js`의 규칙 기반 매칭 로직을 확인한다.
- [ ] `src/main.js`의 라우팅/렌더링 구조를 확인한다.

## Phase 1 — UI/UX 기본 완성
- [ ] 모바일 390px 기준에서 홈/매칭/서류 화면이 깨지지 않도록 CSS를 정리한다.
- [ ] 매칭 결과 탭을 “신청 가능성 높음 / 추가 확인 필요 / 현재 조건상 어려움”으로 명확히 만든다.
- [ ] 혜택 카드에 `왜 추천됐나요?`와 `무엇을 확인해야 하나요?` 영역을 강화한다.
- [ ] 홈 대시보드 상단에 “지금 해야 할 1가지” CTA를 추가한다.

## Phase 2 — 조건 입력 개선
- [ ] 현재 사이드 패널을 3단계 온보딩으로 분리한다.
- [ ] 소득은 정확한 금액 대신 구간으로 입력하게 유지한다.
- [ ] 거주지는 시/도, 시/군/구까지만 받는다.
- [ ] 입력 완료 후 첫 매칭 결과로 자연스럽게 이동한다.

## Phase 3 — 매칭 엔진 고도화
- [ ] `requires_check` 규칙의 영향도를 정책별로 조정할 수 있게 만든다.
- [ ] 필수 조건 불일치 시 점수를 낮추고 사유를 카드에 표시한다.
- [ ] 마감이 지난 정책은 `closed` 상태로 분류한다.
- [ ] 관심 분야와 생애 이벤트 가중치를 별도 함수로 분리한다.

## Phase 4 — 마감/서류 실행 기능
- [ ] 마감 캘린더를 월간 그리드와 리스트 탭으로 나눈다.
- [ ] D-7, D-3, 마감일 상태를 시각적으로 구분한다.
- [ ] 서류 체크리스트의 체크 상태를 localStorage에 저장한다.
- [ ] 정책별 서류 준비율을 홈 대시보드에 반영한다.

## Phase 5 — 신뢰/안전 UX
- [ ] 모든 상세 화면 하단에 “사전 매칭이며 공식 심사 필요” 안내를 둔다.
- [ ] 정책금융상품 카드에는 “가입 권유 아님 / 공식 안내 확인” 배지를 추가한다.
- [ ] 개인정보 초기화 버튼을 설정 화면에 추가한다.
- [ ] 공식 출처 링크 영역을 시각적으로 분리한다.

## Phase 6 — 프리미엄 가치 검증
- [ ] 월 3,900원 프리미엄 Paywall 목업을 만든다.
- [ ] 무제한 매칭, 마감 리마인더, 서류 체크, 정책 변경 요약의 가치를 보여준다.
- [ ] “놓치면 아까운 예상 혜택 규모”를 확정 금액처럼 보이지 않게 표현한다.

## Phase 7 — 데이터 확장 준비
- [ ] 온통청년/정부24 API 연동을 가정한 repository interface 문서를 만든다.
- [ ] mock repository와 api repository를 분리할 수 있게 구조를 정리한다.
- [ ] 정책 갱신일, 변경 이력, 공식 출처 필드를 강화한다.
